# 六大测试方法论 — 设计特点蒸馏（论坛 Web 项目）

> 供 `forum-web-uat` Skill 引用。面向 AI 与人类测试负责人。

---

## 1. James Bach（探索式测试 / 风险驱动）

| 维度 | 设计特点 |
|------|----------|
| 哲学 | 测试是**学习产品**的过程，不是执行固定脚本；好测试员用头脑，不依赖 exhaustive 用例表 |
| 探索式测试 | **同时设计、执行、学习**；用 Session（时间盒）+ Charter（任务章程）组织 |
| 风险驱动 | 先画**风险地图**（什么坏掉最致命），把时间花在高风险区，低风险可抽样 |
| 与论坛落地 | 内测/灰度/UAT：**冒烟确认主路径** → 按章程自由探索边界（并发发帖、断网、奇怪输入） |
| 产出物 | 风险图、Session 记录、缺陷叙事（非仅「步骤 3 失败」） |
| 反对 | 把探索式测试说成「随便点点」；无章程、无记录的 ad-hoc |

**论坛 Charter 示例**：「作为新注册用户，在 90 分钟内尝试破坏发帖审核与权限边界。」

## 2. Cem Kaner（情境驱动 / ISTQB 体系化）

| 维度 | 设计特点 |
|------|----------|
| 哲学 | **没有放之四海而皆准的流程**；测试随产品情境、用户规模、团队成熟度变化 |
| 情境要素 | 业务域（论坛：发帖、评论、审核、邀请码）、利益相关方、质量目标、资源与时间 |
| ISTQB 贡献 | 标准化术语与分级（便于企业沟通），但**不替代**情境判断 |
| 与论坛落地 | MVP 5～50 人：重闭环与权限，轻压测；答辩演示：重 UI 与主路径；公网试点：重安全与准入 |
| 产出物 | 情境说明表 → 由此推导测试范围与**不测什么** |
| 决策问题 | 「我们现在最怕什么？」「用户是谁、在什么网络下用？」 |

## 3. Michael Bolton（四要素 / 与 Bach 的探索式体系）

| 维度 | 设计特点 |
|------|----------|
| 四要素 | **P**roduct（测什么）、**P**roject（约束）、**R**isk（怕什么）、**E**nvironment（在哪测） |
| 标注法 | 每条发现/用例带 P-J-R-E，避免「在错误环境测了错误风险」 |
| 多环境 | 测试服 / 预发布 / 生产行为可能不同；论坛需分别验证网关、HTTPS、demo-login 白名单 |
| 与论坛落地 | 同一功能在 `8091` 与 Docker `80` 各走一遍；记录环境差异导致的假失败 |
| 产出物 | 四要素标签 + 环境矩阵（配置项 × 环境） |
| 启发式 | 「这件事在生产和在本地会一样吗？」 |

## 4. Rex Black（测试管理 / TMMi / 上线准入）

| 维度 | 设计特点 |
|------|----------|
| 哲学 | 测试是**可管理的工程活动**，有计划、度量、缺陷闭环、发布门禁 |
| TMMi | 测试成熟度分级；论坛 MVP 通常在 Level 2～3（有流程、有回归，未必全自动化） |
| 生命周期 | 计划 → 设计 → 执行 → 汇总 → 修复验证 → **上线准入评审** |
| 缺陷闭环 | 发现 → 定级 → 指派 → 修复 → **回归** → 关闭；P0/P1 阻塞发布 |
| 与论坛落地 | Day1 冒烟全绿才 UAT；UAT 结束出**准入检查表**（学生路径+管理路径+安全+移动端） |
| 产出物 | 测试计划摘要、缺陷台账、准入签字表 |

## 5. Jeff Offutt（Web / B-S 专项）

| 维度 | 设计特点 |
|------|----------|
| 专攻 | 浏览器/服务器架构、**表单与输入**、登录会话、权限、前后端集成 |
| 输入点矩阵 | 对每个输入控件列：合法值、边界、非法、安全 payload |
| 论坛适配点 | 注册、登录、发帖、评论、搜索、资料编辑、附件上传、管理端表单 |
| 集成关注 | API 与 UI 状态一致（收藏后列表、审核后可见性） |
| 产出物 | 输入点 × 攻击向量矩阵；集成检查清单 |
| 方法 | 等价类 + 边界值 + 安全字符串（非仅 happy path） |

## 6. James Whittaker（攻击式 / 高负载 / 谷歌式质量）

| 维度 | 设计特点 |
|------|----------|
| 哲学 | 像**攻击者**一样思考：哪里信任了用户输入？哪里默认了身份？ |
| 攻击式测试 | XSS、越权、CSRF、文件上传、信息泄露、速率限制绕过 |
| 性能视角 | 高峰并发（多用户同时发帖/刷列表）；论坛 MVP 可做**轻量**并发而非全压测 |
| 与论坛落地 | 学生 token 调管理 API；存储型 XSS；恶意附件；1 秒内多次登录 |
| 产出物 | 攻击清单勾选；仅报告**可复现**的真实问题 |
| 区分 | 探索式找未知；攻击式针对**已知威胁模型** |
