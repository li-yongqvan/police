# MUI-03A 默认主题移动端验收手册

> 适用版本：Discourse 8080 默认主题 `ai-forum-premium-preview`
>
> 测试目标：确认 MUI-03A 同步到正式默认主题后，移动端话题列表、话题详情、回复编辑器、新建话题编辑器和常用菜单仍然可用，并且没有新的横向溢出或关键按钮空白问题。

## 1. 测试环境

### 1.1 正式地址

- Discourse 首页：`http://122.51.233.225:8080/`
- 最新话题：`http://122.51.233.225:8080/latest`
- 示例话题详情：`http://122.51.233.225:8080/t/ai/5`

### 1.2 视口尺寸

按以下顺序测试：

1. 主移动端尺寸：`390 x 844`
2. 小屏移动端尺寸：`375 x 667`
3. 桌面回归尺寸：`1440 x 900`

### 1.3 测试账号

编辑器相关功能需要登录。使用现有学生或协会管理测试账号，账号信息参考 `docs/demo-accounts.md`。

不要把密码、token、cookie 写入截图、缺陷报告或聊天记录。

## 2. 测试前检查

### T-01 默认主题入口

1. 打开 `http://122.51.233.225:8080/`。
2. 确认地址栏没有 `preview_theme_id`。
3. 页面可以正常加载。
4. 页面没有明显的主题预览提示条。

预期结果：正式入口可访问，当前使用默认主题。

### T-02 横向溢出基线

在浏览器 Console 执行：

```js
Math.max(document.documentElement.scrollWidth, document.body.scrollWidth) - window.innerWidth
```

预期结果：返回 `0`。如果大于 `0`，记录当前页面、视口和返回值。

### T-02B 移动端空白控件基线

在每个移动端页面顶部、列表控制区、帖子操作区和编辑器操作区检查：

- 只有背景色、边框或方块轮廓，但没有可见文字或图标的按钮。
- 图标颜色过浅，在亮色或暗色模式下难以识别的按钮。
- 视觉上无法判断用途、只依赖屏幕阅读器标签的按钮。
- `no-text` 类按钮隐藏文字后也隐藏图标的情况。

预期结果：

- 不出现空白蓝色方块或空白图标按钮。
- 发帖、搜索、导航、筛选、回复、上传、取消、发布等关键控件都有可见文字或清晰图标。
- 暗色模式下控件前景色和背景色有足够对比度。

## 3. 话题列表测试

页面：`http://122.51.233.225:8080/latest`

### T-03 列表与筛选控制

1. 分别在 `390 x 844` 和 `375 x 667` 打开 `/latest`。
2. 检查顶部导航、搜索入口、菜单入口、列表筛选和新建话题入口。
3. 检查话题卡片标题、分类、作者、回复数和时间信息。

预期结果：

- 列表内容可读，不被顶部控件遮挡。
- 筛选、搜索、菜单和新建话题入口都能被识别。
- 页面没有横向滚动。

### T-04 新建话题入口

1. 登录后打开 `/latest`。
2. 点击移动端新建话题入口。

预期结果：

- 新建话题按钮不是空白方块。
- 按钮至少有清晰图标或文字。
- 点击后可以打开新建话题编辑器。

## 4. 话题详情测试

页面：`http://122.51.233.225:8080/t/ai/5`

### T-05 标题和正文阅读

1. 打开话题详情页。
2. 分别在 `390 x 844` 和 `375 x 667` 观察标题、分类、作者、时间和正文。

预期结果：

- 标题可以自然换行，不被右侧控件遮挡。
- 正文段落、引用、代码块、图片和长链接不撑宽页面。
- 页面没有横向滚动。

### T-06 帖子操作区

1. 向下滚动到帖子底部操作区。
2. 检查点赞、收藏、更多操作和回复入口。
3. 点击回复入口。

预期结果：

- 操作图标清晰可见，点击区域足够。
- 回复入口比次要操作更醒目。
- 点击回复后可以打开回复编辑器。

## 5. 回复编辑器测试

### T-07 编辑器整体布局

从 T-06 打开回复编辑器后检查：

- 顶部关闭按钮。
- 最小化或收起按钮。
- 正文输入区。
- 底部回复按钮。
- 底部安全区。

预期结果：

- 编辑器占用合理移动端空间。
- 关闭、最小化和发布控件可见且容易点击。
- 输入区不被顶部或底部控件遮挡。
- 底部按钮不贴边，也不被系统手势区域遮挡。

### T-08 工具栏

1. 观察工具栏是否保持可用。
2. 左右滑动工具栏。
3. 点击一个不会改变发布状态的工具按钮，例如粗体或链接。

预期结果：

- 工具栏不会挤成难以使用的多行布局。
- 工具栏横向滚动不带动页面级横向滚动。
- 图标和按钮文字不跑出屏幕。

### T-09 回复输入和发布

1. 输入 `MUI-03A mobile composer test`。
2. 继续输入较长内容，观察正文区域滚动。
3. 点击回复按钮。
4. 刷新页面或重新打开该话题。

预期结果：

- 输入文字正常显示。
- 正文区域不会无限撑高并遮挡发布按钮。
- 回复按钮可见、可点击。
- 发布成功后内容出现在话题中；如果需要审核，应显示待审核状态。

自动化验收说明：打开编辑器和检查发布按钮属于无副作用检查；真正输入草稿或点击发布会改变站点状态，执行前需要单独确认。

## 6. 新建话题编辑器测试

页面：`http://122.51.233.225:8080/latest`

### T-10 新建话题字段

1. 打开 `/latest`。
2. 点击新建话题入口。
3. 输入标题。
4. 选择分类。
5. 如果显示标签输入，输入一个测试标签。
6. 在正文中输入两到三行文字。
7. 左右滑动工具栏。

预期结果：

- 标题输入框不被遮挡。
- 分类选择器可点击，弹层不超出屏幕。
- 标签区域不会撑宽布局。
- 正文输入区可用。
- 工具栏不会造成页面级横向滚动。

### T-11 新建话题发布

1. 输入临时测试标题，例如 `MUI-03A mobile topic test`。
2. 输入临时测试正文。
3. 点击发布按钮。
4. 返回最新话题列表。

预期结果：

- 发布按钮始终可见，或可以通过正常滚动访问。
- 点击后不会重复提交。
- 发布成功后进入话题详情或返回列表。
- 新话题可在列表中找到，或显示待审核状态。

测试完成后，如果该话题只是临时数据，请按站点权限删除或请管理员清理。

自动化验收说明：打开编辑器和检查发布按钮属于无副作用检查；真正输入草稿或点击发布会改变站点状态，执行前需要单独确认。

## 7. 菜单测试

### T-12 Search Menu

1. 点击顶部搜索入口。
2. 输入搜索词。
3. 关闭搜索菜单。

预期结果：

- 搜索入口图标可见。
- 输入框、关闭按钮和结果区域不超出屏幕。
- 暗色模式下可读。

### T-13 Hamburger Menu

1. 点击顶部汉堡菜单入口。
2. 检查菜单项、滚动和关闭行为。

预期结果：

- 菜单入口图标可见。
- 菜单内容不横向溢出。
- 可以正常关闭。

### T-14 User Menu

1. 登录后点击用户头像或用户菜单入口。
2. 检查通知、个人资料和设置入口。

预期结果：

- 用户菜单入口可识别。
- 菜单内容不遮挡主要操作。
- 可以正常关闭。

## 8. 空值和边界测试

### T-15 空标题或空正文

1. 打开新建话题编辑器。
2. 不填写标题或正文，直接尝试发布。

预期结果：

- 发布被阻止。
- 页面给出明确提示。
- 编辑器不会消失或卡死。

### T-16 超长正文、标题和链接

1. 在回复或新建话题编辑器中输入较长正文。
2. 输入很长的连续字符串或 URL。

预期结果：

- 标题和正文可以换行或在局部区域滚动。
- 不会撑破 `390px` 或 `375px` 页面宽度。
- 发布按钮仍然可用。

## 9. 桌面回归

在 `1440 x 900` 下检查：

- 首页和最新话题列表。
- 话题详情。
- 回复编辑器。
- 新建话题编辑器。
- 搜索菜单、汉堡菜单和用户菜单。

预期结果：

- 桌面布局没有明显变形或错位。
- 移动端 `no-text` 控件规则不影响桌面工具栏。
- 编辑器发布、关闭和最小化控件仍可用。

## 11. 缺陷记录格式

```text
编号：
页面：
视口：
账号角色：
操作步骤：
实际结果：
预期结果：
是否可继续操作：
截图路径：
浏览器与版本：
```

缺陷等级建议：

- P0：无法登录、无法打开编辑器、数据丢失、发布功能完全不可用。
- P1：发布或回复失败、按钮不可见、编辑器被遮挡、页面严重横向溢出。
- P2：局部间距、图标、换行或滚动体验异常，但仍可完成操作。
- P3：轻微视觉差异、文案或对齐问题。

## 12. 通过标准

MUI-03A 通过本轮验收需要满足：

- T-01 至 T-14 在两个移动端尺寸均通过。
- T-02 页面级横向溢出为 `0`。
- 回复和新建话题的发布按钮可见且可操作。
- 搜索、汉堡菜单、用户菜单入口可识别。
- 不出现 P0 或 P1 缺陷。
- 桌面回归没有明显布局破坏。
