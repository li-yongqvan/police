## 1. 情境评估

| 维度 | 现状 | 测试影响 |
|------|------|---------|
| 产品阶段 | MVP 校内试运行 | 核心闭环优先，UI瑕疵容错 |
| 用户规模 | 预计 5～50 人 | 不压测极限，但验证基本并发 |
| 关键业务 | 注册→发帖→评论→审核 | 这是主路径，每条必须过 |
| 风险最高点 | 权限越权、数据丢失 | 100%覆盖，不能有逃逸 |
| 测试环境 | 本地 Docker / 云主机 | 先本地过，再远程验收 |

**测试策略决定**：本次以**全功能体验走查**为主，辅以自动化 API 冒烟，暂不做大规模压测。

## 2. 风险地图

```
🔴 致命风险（必须 100% 覆盖）
├── 普通用户获得管理员权限（垂直越权）
├── 用户 A 访问用户 B 的私密数据（水平越权）
├── SQL 注入 / XSS 存储型注入
├── 帖子数据丢失/被未授权删除
└── 敏感信息泄露（密码、Token）

🟠 严重风险
├── 发帖/评论核心流程中断
├── 登录/注册不可用
├── 审核流程失效（违规内容直接公开）
├── 邀请码被批量滥用
└── 文件上传恶意文件

🟡 中等风险
├── 搜索/浏览体验差
├── 通知未送达
├── 附件上传偶发失败
└── 手机端样式错乱

🟢 低风险
├── 非关键文案错误
├── 次要页面样式偏差
└── 缓存导致的短暂不一致
```

## 4. 测试生命周期

```
┌───────────────────────────────────────────────────────────┐
│  Day 1: 环境准备 + API冒烟全量  →  全部 PASS 才进下一步    │
│  Day 2: 全功能体验走查（学生路径）→  记录所有发现          │
│  Day 3: 全功能体验走查（管理路径）→  记录所有发现          │
│  Day 4: Web安全矩阵 + 攻击式测试  →  只保留真实漏洞        │
│  Day 5: 缺陷汇总 → 定级 → 修复验证 → 上线准入              │
└───────────────────────────────────────────────────────────┘
```

### 4.1 缺陷定级标准

| 等级 | 定义 | 示例 |
|------|------|------|
| **致命 P0** | 核心功能不可用，或安全漏洞可被利用 | 越权、数据丢失、登录失败 |
| **严重 P1** | 主要功能受影响，有 workaround | 发帖成功但提示错误、审核列表不刷新 |
| **一般 P2** | 次要功能异常 | 头像上传后不更新、统计数据延迟 |
| **建议 P3** | 体验优化 | 文案错误、样式微调 |

## 5. Web输入安全矩阵

论坛所有输入点一览 → 每个输入点需要验证以下攻击向量：

| 攻击类型 | Payload 示例 | 测试方法 |
|---------|-------------|---------|
| XSS 注入 | `<script>alert(1)</script>` | 帖子标题、内容、评论、签名、个人简介 |
| XSS img | `<img src=x onerror=alert(1)>` | 富文本/Markdown 输入框 |
| SQL 注入 | `' OR '1'='1' --` | 搜索框、登录框、URL 参数 |
| 超长输入 | 10000 字符 | 标题/内容/用户名 |
| Unicode | `⟨⁄⁄⟩` / 零宽字符 | 昵称、帖子标题 |
| 路径遍历 | `../../../etc/passwd` | 附件上传文件名 |
