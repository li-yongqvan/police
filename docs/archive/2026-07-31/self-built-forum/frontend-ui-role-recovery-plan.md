# AI 智联论坛：前端界面与角色差异 — 问题清单 & 解决计划书

> 编制日期：2026-05-24  
> 背景：云主机已升级 `feature/ai-forum-production` 后端；当前线上前端与 MVP 时期体验不一致，且三种演示账号界面/功能几乎相同。

---

## 一、先说明：仓库里其实有「三套前端」

| 目录 | 界面特征 | 典型用途 |
|------|----------|----------|
| **`frontend/`** | 学院演示 UI：首页三个角色按钮 → `/community` 或 `/admin`；自定义 CSS；中台仅 4 个菜单 | 主工程 README 写的「学院 MVP」 |
| **`frontend-standalone/`** | 与 `frontend/` 同套路，但接 **JSON Mock**，不依赖后端 | 本地答辩 / 离线演示 |
| **`reference/ai-forum-gitee/frontend/`** | 完整产品 UI：顶栏导航、登录/注册、Element Plus、中台 **9 个菜单**（邀请码、板块、敏感词、角色权限等） | Gitee 参考实现 |

**当前云主机（107.172.138.10）Docker 构建的是 `frontend/`（学院演示版）。**

**升级前** 服务器 `/opt/ai-forum` 跑的是 **Gitee 参考版前端**（板块列表 + 登录注册页 + 完整中台），因此你会感觉「和做 MVP 时完全不一样」。

---

## 二、问题可能出现清单

### A. 前端界面与 MVP 不一致

| # | 可能原因 | 现象 | 可能性 |
|---|----------|------|--------|
| A1 | **部署时换了一套前端** | 从 Gitee 完整 UI 换成了 `frontend/` 学院 UI | **高**（已确认） |
| A2 | **Docker 构建的 `frontend/` 缺少样式资源** | 页面简陋、标题显示 `frontend`、布局错乱 | 中 |
| A3 | **你记忆中的 MVP 是 `frontend-standalone`（Mock）** | 本地很精致，线上接真后端后细节不同 | 中 |
| A4 | **浏览器缓存旧版 JS/CSS** | 部分页面像旧版、部分像新版 | 低 |
| A5 | **1Panel 反代缓存** | 刷新后仍看到旧静态资源 | 低 |
| A6 | **Nginx 把 `/` 指错容器** | 偶尔打开到别的站点（如 `new-project-6`） | 低（已改为反代 8888） |

### B. 不同账号登录后界面/功能一样

| # | 可能原因 | 现象 | 可能性 |
|---|----------|------|--------|
| B1 | **协会管理员与中台管理员共用同一套路由** | `demo_admin` 与 `demo_platform_admin` 都进 `/admin`，且 **同一套 4 个菜单** | **高**（代码如此设计） |
| B2 | **前端未按角色隐藏菜单** | 参考版有 9 个中台页，学院版只实现了 4 个，且 **不区分** `admin` / `platform_admin` | **高** |
| B3 | **登录后都手动点进 `/community`** | 管理员也停留在学生社区页，看起来「和学生一样」 | 中 |
| B4 | **`role` 未写入本地会话** | `localStorage` 里角色丢失，路由守卫失效 | 低（demo-login 会写 role） |
| B5 | **后端 JWT `role` 与前端展示角色不一致** | 中台 API 有权限，但 UI 不体现 | 中 |
| B6 | **学生账号误分配了中台角色** | 学生也能进 `/admin` | 低（路由会拦截非 admin） |
| B7 | **三个账号都浏览相同板块/帖子** | 前台内容本就共享，仅 **管理能力** 应不同 | 预期行为（需说明） |

### C. 功能「看起来都有、但用不了」

| # | 可能原因 | 现象 | 可能性 |
|---|----------|------|--------|
| C1 | **学院版前端未对接完整 API** | 邀请码、收藏、附件、楼中楼等无入口 | **高** |
| C2 | **中台部分按钮为占位** | 如「精华帖请在中台完成」类提示 | 中 |
| C3 | **演示账号权限未写入 `user_roles` 表** | 中台 API 403，但页面仍能打开 | 低（迁移 004 已写） |

## 三、根因归纳（一句话）

1. **界面问题**：线上故意（但未经你确认）部署了 **学院简化前端**，覆盖了原先的 **Gitee 完整前端**。  
2. **角色问题**：学院前端 MVP **只做了「学生社区 / 管理员中台」两档**，且 **两种管理员共用同一中台界面**，没有实现产品文档里的细粒度 RBAC 展示。

### 阶段 2：角色与权限差异化（2–3 天）

**目标：三种账号「一眼能分出差异」。**

| 角色 | 默认落地页 | 可见能力（前端） |
|------|------------|------------------|
| `demo_student` | `/community` | 浏览、发帖、评论、点赞；**无**中台入口 |
| `demo_admin` | `/admin` | 审核、帖子管理、用户封禁、板块开关（协会范围） |
| `demo_platform_admin` | `/admin` | 在协会能力之上，增加：邀请码、敏感词、角色权限、统计大屏 |

**任务拆分：**

| 序号 | 任务 | 交付 |
|------|------|------|
| 2.1 | 路由守卫：按 `role` 限制 `/admin` 子路由 | `router.js` + 菜单 `v-if` |
| 2.2 | 中台侧栏按角色渲染不同 `nav` 配置 | `adminNav.js` 配置表 |
| 2.3 | 社区顶栏：仅 `admin`/`platform_admin` 显示「进入中台」 | `CommunityLayout.vue` |
| 2.4 | 登录成功强制跳转（已实现，需防用户手动回 `/` 后迷路） | 登录页增加「当前角色：xxx」 |
| 2.5 | 后端：中台 API 校验 JWT `role` / `user_roles` | 防止越权调用 |
| 2.6 | 若用 Gitee 前端：启用其 `requiresAdmin` + 按 `payload.role` 控菜单 | 参考版已有基础，需接真 JWT |
