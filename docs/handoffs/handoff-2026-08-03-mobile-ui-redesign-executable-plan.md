# Handoff - 2026-08-03 - Mobile UI Redesign Executable Plan

## 1. 本轮目标

本轮目标是把移动端 UI 修改意见收敛成可执行方案，并在用户确认后按 Ticket 实施。

范围同时包含两部分，但必须拆开交付：

- 平台前端：登录页、管理端抽屉、管理端顶部栏。
- Discourse 论坛主题：移动端 header、触控尺寸、话题列表信息层级。

## 2. 已确认需求口径

### 2.1 验收环境

- 云服务器真实环境是最终验收标准。
- 本地环境只做部署前预检，包括构建、基础冒烟和明显布局错误检查。
- 平台前端最终通过云服务器 `8888` 入口验收。
- Discourse 主题最终在云端 Discourse 主题预览中验收，通过后再决定是否设为正式主题。

### 2.2 登录验证

- 当前统一密码口径：以用户确认的统一密码为准。
- 普通用户登录验证：从数据库中读取任意一个 QQ 号作为用户名，使用统一密码验证是否可登录。
- QQ 号账号只用于普通用户链路，不用于管理端验收。
- QQ 号登录成功标准：
  - 平台登录成功；
  - 自动进入 Discourse；
  - 能确认当前处于已登录状态；
  - 全程只读，不发帖、不回复、不点赞。
- 管理员登录验证：使用 `demo_admin` 加统一密码。
- 如管理员登录仍失败，停止试错并汇报，不继续猜测其他账号或密码。

### 2.3 改动范围

本轮只处理已经确认的问题：

- 管理端移动抽屉错位。
- 管理端顶部触控尺寸不足。
- 登录页横屏首屏可操作性不足。
- Discourse 移动主题触控尺寸、header 和话题列表层级问题。

如果遇到突发情况，必须先停止并向用户汇报，不主动扩大修复范围。

### 2.4 移动端紧凑态规则

当移动端空间紧张导致中文按钮无法完整摆放时：

- 优先使用清晰图标表达动作。
- 图标不足以表达时，允许保留一个最具代表性的汉字。
- 即使视觉上只显示图标或单字，也必须保留 `aria-label` 或等效语义。
- 正常宽度下仍优先显示完整文案。
- 该规则同时适用于平台前端和 Discourse 移动主题。

管理端顶部栏补充规则：

- 正常移动竖屏显示 `AI 智联 · 管理端`。
- 紧凑横屏允许缩短为 `管理端`。
- 操作按钮优先保证可点击，不允许品牌文字挤压操作区。

## 3. Ticket 拆分

### Ticket MUI-01 - 平台前端移动修复

优先级：P1/P2 混合，作为第一批上线。

改动项：

1. 修复管理端移动抽屉错位。
   - 重点文件：`frontend/src/styles/gx-theme.css`
   - 重点检查重复的 `.gx-admin-shell .gx-admin-sidebar` 移动端规则。
   - 不能只重复添加 `left: 0` 和 `transform: translateX(0)`，需要先确认 `left = -24px` 的真实来源。
   - 目标：抽屉打开后左边界为 0，导航文字完整可读。

2. 补齐管理端顶部栏触控尺寸。
   - 重点文件：`frontend/src/views/AdminLayout.vue`
   - 菜单按钮和退出按钮点击区域不小于 44px。
   - 紧凑横屏允许缩短品牌文字，按钮可图标化或单字化，但需保留语义。

3. 优化登录页横屏首屏可操作性。
   - 重点文件：`frontend/src/components/gx/GxAuthShell.vue`
   - 只做现有单列布局的间距压缩和尺寸调整。
   - 如果压缩后仍无法让账号和密码输入框在首屏可见，停止并汇报，不擅自改为左右分栏或重做登录页结构。

预检：

- 本地构建通过。
- 本地基础冒烟通过。
- 390x844、375x667、667x375 视口下无明显横向溢出和遮挡。

上线前确认：

- Ticket MUI-01 完成本地预检后，必须先向用户汇报具体改动和预检结果。
- 只有用户确认后，才允许部署云服务器。

云端验收：

- 入口：`http://122.51.233.225:8888/`
- 视口：390x844、375x667、667x375。
- 页面：`/`、`/admin`、`/admin/users`、`/admin/invites`。
- 普通 QQ 号登录链路只读验证。
- `demo_admin` 管理端登录链路验证。

### Ticket MUI-02 - Discourse 移动主题修复

优先级：P1/P2，作为第二批上线。

改动项：

1. 移动端 header。
   - 统一 header 高度和图标触控区域。
   - 登录、搜索、菜单、账户入口不小于 44px 或保持等效可点击区域。

2. 话题列表。
   - 优化标题、摘要、分类、回复数、时间的移动端信息层级。
   - 标题和摘要需要有行数约束，避免首屏被单条长内容挤满。

3. 紧凑态表达。
   - 与平台前端保持一致：图标优先，单字兜底，保留语义。

边界：

- 只改 Discourse 主题目录，不在 Vue 登录页中硬改论坛体验。
- 目标目录：`discourse-themes/ai-forum-premium-preview/`

上线前确认：

- 主题修改后先打包并在云端 Discourse 主题预览中验收。
- 预览通过后，向用户汇报，再由用户确认是否设为正式主题。

云端验收：

- 入口：`http://122.51.233.225:8080/`
- 视口：390x844、667x375。
- 全程只读，不发帖、不回复、不点赞、不改论坛配置。

## 4. 发布节奏

采用两批上线：

1. 第一批：平台前端移动端修复。
2. 第二批：Discourse 移动主题修复。

代码按 Ticket 分别提交和推送；部署按两批执行。不能把平台前端和 Discourse 主题混在同一个上线动作中。

## 5. 停止条件

遇到以下情况必须停止并汇报：

- 发现需要超出本轮确认范围的改动。
- 登录账号口径不符合预期。
- `demo_admin` 使用统一密码登录失败。
- QQ 号普通账号使用统一密码登录失败。
- 本地预检发现结构性问题，需要重做布局方案。
- Discourse 主题预览无法准确反映线上正式主题效果。
- 需要执行线上写操作，包括发帖、回复、点赞、收藏、封禁、删除、改等级、生成或作废邀请码、修改生产配置。
