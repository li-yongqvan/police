## Context

User reported that avatars could appear to reset after navigating between boards, and that other users' post/comment avatars sometimes did not reflect avatars set in profile. Investigation against the deployed API showed `/users/me` retained the current user's avatar and the uploaded image URL returned 200, but forum post and comment endpoints did not include `author_avatar`.

## Outcome

Added `author_avatar` to forum post list items, post details, and comments. Updated post list, collection list, post detail, comment list, and create-comment queries to read `schema_auth.users.avatar` alongside `username`, so frontend author chips can render profile avatars for other users.

Updated `GxAvatarInitial` so a transient image load error falls back briefly and retries the same avatar URL up to two times with a cache-busting query parameter. A genuinely missing image still falls back to the initial rather than retrying indefinitely.

Validated with `go test ./...` in `services/forum` and `npm run build` in `frontend`.

## Follow-ups

- After deployment, verify public `/forum-api/api/v1/posts`, `/forum-api/api/v1/posts/:id`, and `/forum-api/api/v1/posts/:id/comments` responses include `author_avatar`.
- The unrelated untracked `design-concepts/` directory and `services/user/migrations/009_qq_number_login_accounts.up.sql` file remain untouched.
