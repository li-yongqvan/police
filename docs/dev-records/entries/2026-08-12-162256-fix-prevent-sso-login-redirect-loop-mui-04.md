## Context

During MUI-04 preview validation the user reported that clicking login on either
`8080` or `8888` briefly opened the login page and then jumped back. Inspection
showed a stale-login-state loop: the platform SPA trusted `localStorage`
immediately and redirected to Discourse SSO, while the SSO endpoint only trusts
the `ai-forum-token` cookie. If the cookie was missing or stale, SSO redirected
back to the platform login page and the cycle repeated.

## Outcome

The frontend session store now validates a stored token through `/users/me`
before route guards use it for automatic login redirects. Valid tokens restore
the SSO cookie; invalid tokens are cleared so the user remains on the login page
instead of being sent back into SSO.

Validation:
- `npx vitest run tests/unit/sessionStore.test.js`
- `npm run build`
- `node work/check-login-loop.mjs`

Full `npm run test:unit` still has pre-existing failures unrelated to this
change: tests reference missing `buildCommentTree` / `useFeedSort` modules, and
`userApi.register` test expectations do not match the current API signature.
