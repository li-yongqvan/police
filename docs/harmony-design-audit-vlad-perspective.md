# Harmony 视角设计审视：AI智联校园论坛还缺什么？

> **写作视角**：以 NodeBB Harmony 主题设计者 Vlad Gerasimov 一贯的主张为参照——**内容优先、侧栏导航、克制装饰、阅读宽度可控、层次靠排版而非堆组件**。  
> **审视对象**：当前已上线的社区前端（Harmony 改造一、二期 + 登录/详情/个人中心局部精修之后）。  
> **性质**：产品/体验诊断，非开发任务清单；优先级供讨论。

---

## 1. 一句话结论

骨架已经像论坛了，但**还没有像一本「可以长时间读下去」的出版物**。  
你们做对了导航与限宽的方向，却仍有几处典型的「工程师拼装感」：**首页像门户、社区像浅色应用、登录像另一个产品、管理端像第三个产品**。Harmony 的核心不是圆角和侧栏，而是**整条阅读链路上的安静与一致**。

---

## 2. 已经做对的（值得保留）

| 方向 | 现状 | 为何符合 Harmony |
|------|------|------------------|
| 持久侧栏 | `GxSiteSidebar` + `gx-community-shell` | 浏览型产品应以空间结构稳定为先，减少每页重新找入口 |
| 阅读限宽 | `--gx-reading-max`（约 42rem）用于帖子详情 | 长文舒适区在 60–75 字符/行，过宽会疲劳 |
| 帖子列表行化 | `GxPostCard` `variant="list"` | 信息流应像索引，而不是一排小海报 |
| 详情页分层 | 标题区 / 正文 / 评论 / 侧栏元信息 | 把「读」和「管」拆开，比六颗大按钮堆在侧栏好得多 |
| 设计 token 起步 | `gx-theme.css` 中 primary / accent / spacing | 没有 token，后面每一次改版都会更贵 |

这些不是装饰，是**信息架构**。请不要再推翻侧栏和限宽，应在上面打磨细节。

---

## 3. 最缺的东西：一套「单一皮肤」

### 3.1 三个产品叠在一起

当前用户会连续经历：

1. **登录/注册** — 深色、全屏、偏 Spotify 的科技背景  
2. **社区** — 浅灰底、白卡片、警院蓝红金 token  
3. **管理端** — 另一套 Admin 布局与表格审美  

从 Vlad 的角度看，这不是「主题变体」，而是**三个没有共享排版契约的应用**。用户不会说「主题切换」，只会说「怎么进个论坛风格全变了」。

**建议方向**（原则层面）：

- 选定**一种主背景策略**（全站浅 / 全站深 / 仅阅读区浅），登录页也应是同一 token 的变奏，而不是另一套色相。  
- 登录可以戏剧化，但应使用**同一套字号阶梯、按钮高度、圆角半径**；深色只是 `surface-inverse`，不是新设计系统。

### 3.2 Token 有了，但「执行不完整」

已有 `--gx-reading-max`、`text-display/title/body/meta`，但实践中仍常见：

- 同一语义（区块标题）在首页、板块、详情、个人中心用不同组合（`text-title` + Card + 自定义 margin）  
- 时间、统计、标签三种 meta 信息**视觉权重打架**（你们刚修过 ISO 时间，说明 meta 管线尚未统一）  
- 红色 accent 同时承担：板块标签、置顶、举报、错误——**语义过载**

Harmony 会坚持：**一种颜色只干一件事**。警院红可以保留，但要规定「仅用于警示/举报/未读」，不要与「社团板块」「置顶」共用同一刺激色。

---

## 4. 首页：仍不像「阅读入口」，而像「校园门户」

### 4.1 焦点过多

首页同时存在：

- 轮播 `GxCarousel`  
- 置顶区（card 变体，与列表行混用）  
- 最新帖子列表  
- 右侧统计卡片（用户数、今日发帖、板块名串）  

读者进入时眼睛不知道**先看哪里**。Harmony 首页更接近：**一条时间线 + 极少的次要模块**；统计与运营位应退到二级或折叠。

### 4.2 列表与卡片混用

置顶用 `variant="card"`，流用 `variant="list"`——逻辑上合理，视觉上像两个频道拼贴。  
更 Harmony 的做法：

- 置顶仅用**行样式 + 左侧色条/图标**（你们已有 `--pinned` / `--announce` 思路），不要突然变海报卡；  
- 或置顶最多 1 条「featured」大卡，其余全部 list。

### 4.3 轮播与论坛阅读文化相悖

轮播是门户语言（宣传、活动、招商）。论坛用户来是为了**扫标题、判断要不要点进去**。  
若内容运营确实需要轮播，应：

- 高度压低、自动播放关闭、默认静态；  
- 或移到侧栏最底部，绝不要占据首屏黄金区。

---

## 5. 阅读链：帖子列表 → 详情 → 评论

### 5.1 列表行还缺「人的形状」

`GxPostCard` 行模式已有板块 Badge、标题、作者、日期、回复/赞。但 Harmony / Discourse 一类产品通常在行首有**稳定 avatar 列**（哪怕只是首字母圆），形成纵向扫描节奏。

现在作者名与统计挤在 footer 一行，**扫描路径是 Z 字形**，不如「左头像 · 中标题 · 右日期」清晰。

### 5.2 详情页进步了，但评论仍像附件

详情已合并为单 Card + `GxCommentThread`，比早期双白盒好。仍缺：

- 评论与正文的**层级差**不够（都是 15px 正文灰字）  
- 缺少「第 N 楼」或线程感（扁平列表对长讨论不友好）  
- 作者 chip 在评论里复用，但时间格式与列表/侧栏尚未统一策略（日期 vs 日期+时间）

**Harmony 主张**：正文是主角，评论是配角——配角应更小一号、更灰、更紧，而不是另一个几乎同权的表单块。

### 5.3 写作页（发帖/编辑）不在阅读模式里

`NewPost` / `EditPost` 仍是标准表单页，没有「写作通道」：

- 无全宽/限宽切换  
- 无 Markdown 或富文本预览节奏  
- 与读帖时的 typography 不一致  

发帖是论坛的第二核心场景，应至少共享**正文字号、行高、段落间距**。

---

## 6. 导航：三套系统并存

| 层级 | 组件 | 问题 |
|------|------|------|
| 桌面 | 侧栏 + 顶栏搜索/用户 | 顶栏与侧栏功能部分重叠（「首页」在两侧都能到达） |
| 移动 | 抽屉侧栏 + 底栏 Tab + 顶栏菜单 | 三套入口，认知成本高 |
| 板块 | `GX_MOBILE_TABS` 里「板块」指向固定 slug | 易与侧栏四个板块不一致 |

Harmony 移动端通常是：**一个主导航（底栏或侧栏）+ 极薄顶栏**。  
建议原则：桌面以侧栏为主；移动以底栏为主；顶栏只保留搜索与一个账户入口，不要再承载完整 IA。

---

## 7. 尚未「Harmony 化」的页面

这些页面仍明显是 MVP / 通用组件堆叠，与社区首页不在同一完成度：

| 页面 | 主要问题 |
|------|----------|
| **消息中心** `MessagesView` | 传统 Tab + Card 列表，无 inbox 密度优化，无已读/未读视觉系统 |
| **关于本站** `AboutView` | 与社区设计语言关联弱 |
| **用户公开页** `UserPublic` | 有 chip 但仍像资料卡，缺「TA 的主题/回复」时间线 |
| **管理端** 全套 Admin | 功能优先可以理解，但若管理员也从社区跳入，断裂感极强 |
| **搜索** | 仅 query 高亮条，无筛选、无排序、无空状态插画/文案体系 |

Harmony 不是「只装修热门页」，而是**全站默认安静**；未触及的页面会拉低整体品质感。

---

## 8. 微交互、状态与反馈

Vlad 的风格不是炫动效，而是**状态可读**：

- 列表行是否已读、是否已赞、是否已收藏——目前在列表不可见，必须点进详情  
- 按钮 loading、空列表、网络错误——部分页面有 Alert/flash，无统一 empty 组件  
-  hover / focus — 列表行有 hover 边框，但键盘焦点路径未系统测试  
- 过渡 — 几乎无 page transition，可接受，但侧栏抽屉、Tab 切换可 150ms ease

缺的不是动画，是**「我现在在哪、发生了什么」的即时反馈**。

## 9. 排版与中文阅读

### 9.1 字号阶梯未封顶

建议冻结五级并全站强制：

1. Display — 仅帖子标题、板块名  
2. Title — 区块标题（最新帖子、评论区）  
3. Body — 正文、表单  
4. Meta — 日期、统计、面包屑  
5. Caption — 脚注、辅助说明  

现在最大问题是 **Meta 当 Body 用**（说明文字过长、与标题抢戏）。

### 9.2 中文标点与文案节奏

警校场景需要庄重，但 UI 文案不必公文腔。  
登录、发帖、报错应同一语气（简短、主动语态、一句一义）。

### 9.3 数字与日期

已改为 `YYYY-MM-DD` 是正确一步。  
下一步：全站禁止在 UI 层展示原始 ISO；meta 一律走 `formatDisplayDate` / `formatDisplayTime` 管道。

---

## 10. 可访问性与包容性（Harmony 也会在意）

- 侧栏图标+文字好，但需保证 **active 态不仅靠颜色**（已有 background，继续保持）  
- 深色登录与浅色社区切换，对弱视用户可能刺眼；考虑 `prefers-color-scheme` 或用户偏好持久化  
- 触摸目标：底栏 Tab、工具栏按钮已接近 44px，表单次要按钮仍偏小  
- 图片/头像：大量仅首字母，色盲用户靠位置区分作者——列表加 avatar 列可改善

---

## 11. 与「警校论坛」品牌的关系

Harmony 本质是**中性的阅读框架**；警院蓝、金、红是**品牌层**。  
当前风险是品牌色侵入每一个组件（边框、按钮、标签），导致**内容标题反而不再是视觉锚点**。

建议分层：

```
Layer 0 — 中性灰阶（90% 界面）
Layer 1 — 品牌主色（导航 active、主按钮）
Layer 2 — 语义色（成功/警告/错误/置顶）
Layer 3 — 板块识别色（仅 Badge 小面积）
```

---

## 12. 若只能做五件事（优先级）

按 Harmony ROI 排序，供产品/前端排期：

1. **统一设计系统执行** — 一页规范 + 禁止页面级随意 Card/间距；登录纳入同一 token  
2. **首页减法** — 轮播降级或移除；置顶改 list+标记；侧栏统计合并为一条 meta 行  
3. **列表行 avatar + 扫描列** — 稳定三列栅格（头像 | 标题区 | 日期/统计）  
4. **消息/搜索/写作页补齐** — 与社区同构的 layout shell，而非孤立表单  
5. **语义色与 meta 管线** — 时间、标签、状态各一种样式；accent 不再兼职

---

## 13. 结语（Vlad 口吻）

我不关心你们是否「像 Spotify」或「像 NodeBB 截图」。  
我关心的是：一个学生在晚上十点打开帖子，能不能**不被界面打扰地读完，并愿意写下一条评论**。

你们已经有了侧栏和阅读宽度——这是门槛。  
接下来请停止往首页加东西，开始**删掉争夺注意力的模块**，并让每一条帖子列表行、每一页未改过的角落，都服从同一套安静的排版法律。

当用户说不出「这个页面换过设计」而只觉得「这论坛挺好读」时，Harmony 才算真正落地。
