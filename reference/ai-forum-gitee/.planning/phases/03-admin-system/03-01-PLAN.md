## Existing Patterns (from Phase 2)

All services follow: Handler → Service → Model pattern with Gin + pgxpool.
- auth middleware validates JWT and sets user_id/username/level in gin.Context
- Database uses schema isolation (schema_auth, schema_forum, schema_admin)
- Internal service calls use /internal/v1/ prefix (per D-09, no extra auth)
- Redis stores refresh tokens with key pattern "refresh:{user_id}"
- Sensitive word cache: in-memory map with sync.RWMutex, loaded on startup

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin browser → admin-service API | Admin UI sends JWT tokens; auth middleware validates role claims |
| admin-service → forum-service /internal/v1/ | Internal network calls, no extra auth per D-09 (Docker internal network isolation) |
| admin-service → user-service /internal/v1/ | Internal network calls, no extra auth per D-09 |
| forum-service → admin-service /internal/v1/moderation/check | Sensitive word check, internal only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | admin-service AuthMiddleware | mitigate | JWT token validation with role claim check; reject non-admin roles with 403 |
| T-03-02 | Tampering | system_config updates | mitigate | Require admin role; log all config changes to operation_logs with operator_id |
| T-03-03 | Repudiation | Admin actions (ban, approve, delete) | mitigate | Every admin action writes to operation_logs with operator_id, action, target, timestamp, detail JSONB |
| T-03-04 | Information Disclosure | user listing, operation logs | mitigate | Only accessible to authenticated admin users; JWT role check in middleware |
| T-03-05 | Elevation of Privilege | role assignment | mitigate | Only platform_admin role can assign/remove roles; require_permission("manage_roles") check |
| T-03-06 | Denial of Service | Batch delete, user listing without limit | mitigate | Pagination enforced in all list endpoints (max 100/page); batch delete limited to 100 posts per call |
| T-03-07 | Spoofing | Internal service calls (D-09) | accept | Docker Compose internal network isolation sufficient for MVP; no external exposure of /internal/v1/ routes |
| T-03-08 | Tampering | Ban user + Redis token deletion | mitigate | Atomic: set user status='banned' THEN delete Redis refresh token; refresh token loop already checks status='banned' |
