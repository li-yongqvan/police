# AI智联论坛 MVP Roadmap

**Created:** 2026-05-21
**Requirements:** 53 v1 requirements mapped across 5 phases
**Core Value:** 让AI学习者能快速找到技术同伴、交流心得、获取资源，同时通过中台实现论坛全流程可控可管可分析。

---

## Phase 1: 基础设施与项目骨架

**Goal:** 搭建完整的开发基础设施，包括Docker Compose编排、数据库schema、Nginx网关、以及三个Go微服务的项目骨架，确保服务间可以互相通信。

**Status:** Completed

**Requirements:**
- INFRA-01: Docker Compose编排所有服务
- INFRA-02: 三个服务使用独立PostgreSQL schema隔离数据
- INFRA-03: 服务间通过REST API进行内部通信
- FE-04: Nginx反向代理前端和各后端服务API路由

**Success Criteria:**
1. 执行 `docker-compose up` 后所有服务正常启动
2. 三个Go服务可通过各自端口响应健康检查
3. 通过Nginx网关可访问各服务API
4. 数据库schema（schema_auth, schema_forum, schema_admin）已创建

**Technical Notes:**
- 技术栈：Go + Gin, Vue 3 + Vite, PostgreSQL 16, Redis 7, Nginx
- 目录结构：services/user/, services/forum/, services/admin/, frontend/, nginx/
- 每个服务包含 cmd/, internal/{handler,service,model,middleware}/, pkg/
- PostgreSQL使用独立schema隔离，共享实例

## Phase 2: 用户端核心功能

**Goal:** 完成用户邀请码注册/登录系统、用户等级体系（Level 0~5+）、三大板块、发帖/评论/点赞/收藏/附件上传功能，以及用户端Vue前端界面，支持PC+移动端H5自适应。

**Status:** Completed

**Requirements:**
- AUTH-01: 用户可通过邀请码注册账号（注册时设置用户名+密码，无需手机号）
- AUTH-02: 用户可通过用户名+密码登录
- AUTH-03: 用户可查看和编辑个人资料（含等级展示）
- AUTH-04: 用户可上传和更换头像
- AUTH-05: 用户登录后会话保持有效
- LEVEL-01: 用户注册后默认为Level 0（游客），仅可浏览帖子
- LEVEL-02: Level 1（初级会员）可发帖、评论
- LEVEL-03: Level 2（中级会员）可发帖、评论、上传图片/附件
- LEVEL-06: 发帖/评论/上传附件等操作根据用户等级进行权限校验
- INVITE-01: 中台管理员可生成单个邀请码
- INVITE-02: 中台管理员可批量生成邀请码（指定数量）
- BOARD-01: 系统初始化三大核心板块
- BOARD-02: 用户可浏览板块列表
- POST-01: 用户可创建图文帖子
- POST-02: 用户可编辑自己的帖子
- POST-03: 用户可删除自己的帖子
- POST-04: 用户可浏览帖子列表
- POST-05: 用户可查看帖子详情
- COMM-01: 用户可在帖子下回复评论
- COMM-02: 用户可查看帖子的评论列表
- INTER-01: 用户可点赞帖子
- INTER-02: 用户可收藏帖子
- ATTACH-01: 用户可在发帖/评论中上传图片
- ATTACH-02: 用户可分享网盘链接
- ATTACH-03: 用户可上传文档文件
- ATTACH-04: 用户可下载/查看已上传的附件
- FE-01: 用户端支持PC端浏览和发帖
- FE-02: 用户端支持移动端H5自适应浏览
- MOD-01: 发帖/评论提交时自动校验敏感词

**Success Criteria:**
1. 用户凭邀请码完成注册，注册后为Level 0游客
2. 用户可在三大板块发帖（含图文和附件），Level 0仅可浏览
3. 用户可对帖子评论、点赞、收藏，等级权限生效
4. 发帖时自动敏感词校验，含敏感词的帖子被拦截
5. 前端在PC和移动端均可正常浏览和操作

**Technical Notes:**
- user-service: JWT认证、用户CRUD、头像上传
- forum-service: 帖子CRUD、评论、点赞、收藏、附件管理、板块管理
- 发帖时forum-service同步调用admin-service做敏感词校验
- 附件存储：MVP阶段使用本地文件系统，预留对象存储接口
- 前端：Vue 3 + Vite + Vue Router + Pinia + Axios

**Plans:** 1 plan

Plans:
- [x] 02-01-PLAN.md — 完整实现：数据库迁移(3服务) + user-service(注册/登录/头像/等级) + forum-service(板块/帖子/评论/点赞/收藏/附件) + admin-service(邀请码生成/敏感词) + 前端Vue视图(注册/登录/板块/帖子/个人资料/响应式)

## Phase 3: 中台管理与审核系统

**Goal:** 完成中台管控服务的管理功能（系统配置、权限管理）、内容审核通道（待审核列表、审核通过/驳回）、用户管理（封禁、列表、等级升降）、邀请码管理（查看使用状态、作废），以及中台管理端前端界面。

**Requirements:**
- POST-06: 管理员可删除任意帖子
- POST-07: 管理员可设置帖子为精华帖
- POST-08: 管理员可设置帖子为置顶帖
- ADMIN-01: 管理员可在后台浏览待审核帖子列表
- ADMIN-02: 管理员可审核通过帖子
- ADMIN-03: 管理员可审核驳回帖子
- ADMIN-04: 管理员可批量删除违规内容
- USER-ADMIN-01: 中台管理员可封禁用户账号
- USER-ADMIN-02: 中台管理员可查看所有用户列表
- USER-ADMIN-03: 中台管理员可手动升级用户等级（Level 0 → Level 1+）
- USER-ADMIN-04: 中台管理员可查看用户当前等级和操作日志
- LEVEL-04: Level 3（高级会员）可发帖、评论、上传附件、设置精华帖（需管理员角色配合）
- LEVEL-05: Level 4+ 权限逐级递增，由中台配置各等级操作权限
- INVITE-03: 中台管理员可查看邀请码使用状态（已使用/未使用/过期）
- INVITE-04: 邀请码绑定注册记录，可追溯哪个邀请码注册了哪个用户
- INVITE-05: 中台管理员可作废未使用的邀请码
- CONFIG-01: 中台管理员可查看和修改系统配置
- CONFIG-02: 中台管理员可分配简单角色权限
- BOARD-03: 管理员可在中台新增/编辑/删除板块
- MOD-02: 中台管理员可添加敏感词到规则表
- FE-03: 中台管理端支持PC端管理界面

**Success Criteria:**
1. 中台管理员可登录管理后台
2. 可查看待审核帖子列表，并进行通过/驳回操作
3. 可封禁用户、删除帖子、设置精华/置顶
4. 可手动升级/降级用户等级，等级权限即时生效
5. 可查看邀请码使用状态、作废未使用邀请码、追溯注册记录
6. 可修改系统配置（发帖限制、板块开关）
7. 可管理敏感词规则和角色权限

**Technical Notes:**
- admin-service: 系统配置CRUD、审核流程、用户管理、敏感词管理、等级管理、邀请码管理
- 发帖时含敏感词的帖子进入待审核状态（而非直接发布）
- 中台前端：独立Vue应用或同应用不同路由
- 角色体系：普通用户/管理员/中台管理员
- users表增加level字段，每次操作前校验等级权限

**Plans:** 1 plan

Plans:

## Phase 4: 数据统计与报表

**Requirements:**
- ANAL-01: 中台可查看核心数据概览
- ANAL-02: 中台可查看每日统计报表

**Success Criteria:**
1. 中台首页展示核心数据（注册用户数、日发帖量、板块活跃度）
2. 可查看按日的历史统计报表
3. 数据可视化展示（图表形式）

**Technical Notes:**
- admin-service: 定时任务拉取user-service和forum-service统计数据
- statistics_daily表存储每日聚合数据
- 前端使用图表库（如ECharts）可视化展示

## Phase Dependencies

```
Phase 1 (基础设施) ──┬──→ Phase 2 (用户端) ──→ Phase 3 (中台管理) ──┐
                      │                                              ├──→ Phase 5 (集成测试)
                      └──────────────────────────────────────────────┘
Phase 4 (数据统计) ─────────────────────────────────────→ Phase 5 (集成测试)
```

- Phase 2 depends on Phase 1 (基础设施就绪)
- Phase 3 depends on Phase 2 (论坛核心API就绪，中台可对接)
- Phase 4 depends on Phase 3 (中台框架就绪，可添加统计模块)
- Phase 5 depends on Phase 2 + Phase 3 + Phase 4
